1. Thông tin hệ thống chuẩn
---------------------------
Mục tiêu triển khai:
- Domain ứng dụng: https://checkin.joydigi.net
- Repository: git@github.com:leminphuong/joydigi-hr.git
- Thư mục ứng dụng: /var/www/joydigi-hr
- Linux user chạy service: root
- Virtualenv: /var/www/joydigi-hr/venv
- Django WSGI: joydigi.wsgi:application
- Gunicorn bind: 127.0.0.1:8000
- systemd service: joydigi-hr.service
- Nginx thực tế: aaPanel Nginx tại /www/server/nginx/sbin/nginx
- aaPanel vhost: /www/server/panel/vhost/nginx/checkin.joydigi.net.conf
- PostgreSQL host: localhost:5432
- PostgreSQL role: postgres
- Database: joydigi_hr
- Connection URL hiện tại: postgresql://postgres:admin123@localhost:5432/joydigi_hr
- SSL certificate: /etc/letsencrypt/live/checkin.joydigi.net/fullchain.pem
- SSL private key: /etc/letsencrypt/live/checkin.joydigi.net/privkey.pem

NOTE BẢO MẬT: mật khẩu admin123 là thông tin nhạy cảm và khá yếu. Sau khi triển khai ổn định nên đổi sang mật khẩu mạnh, cập nhật .env và restart joydigi-hr. Không commit .env lên GitHub.

2. Kiến trúc hoạt động
----------------------
Internet
  -> checkin.joydigi.net
  -> aaPanel Nginx :80 / :443
  -> proxy_pass http://127.0.0.1:8000
  -> Gunicorn
  -> Django (joydigi.wsgi:application)
  -> PostgreSQL localhost:5432
  -> database joydigi_hr

PostgreSQL không cần domain riêng và không cần mở port 5432 ra Internet khi Django và PostgreSQL chạy cùng VPS.

Các warning hiện tại không làm app chết:

- Accessing database during app initialization -> nên bỏ query DB khỏi AppConfig.ready()/import-time.
- Python 3.10 Google API FutureWarning -> nên lên Python 3.11/3.12 khi có lịch bảo trì.
- Static duplicate candidate.js / pipeline.js -> Django lấy file gặp đầu tiên; kiểm tra lại nếu UI có lỗi.

9. Tạo systemd Gunicorn service
-------------------------------
Tạo file:

nano /etc/systemd/system/joydigi-hr.service

Nội dung chuẩn:

[Unit]
Description=JoyDigi HR Django Gunicorn
After=network.target postgresql.service

[Service]
Type=simple
User=root
Group=root
WorkingDirectory=/var/www/joydigi-hr
Environment="PATH=/var/www/joydigi-hr/venv/bin"
ExecStart=/var/www/joydigi-hr/venv/bin/gunicorn --workers 3 --bind 127.0.0.1:8000 --timeout 120 --access-logfile - --error-logfile - joydigi.wsgi:application
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

Áp dụng:

systemctl daemon-reload
systemctl enable joydigi-hr
systemctl restart joydigi-hr
systemctl status joydigi-hr --no-pager -l

Kiểm tra port:

ss -lntp | grep 8000

Test local:

curl -I http://127.0.0.1:8000

HTTP/1.1 302 Found + Location: /login/?next=/ là ĐÚNG vì trang chủ yêu cầu đăng nhập.

10. aaPanel Nginx - lưu ý rất quan trọng
----------------------------------------
VPS này có Nginx Ubuntu và Nginx của aaPanel. Nginx thực sự đang chạy là:

/www/server/nginx/sbin/nginx

Cấu hình chính:

/www/server/nginx/conf/nginx.conf

Vhost:

/www/server/panel/vhost/nginx/checkin.joydigi.net.conf

Do đó KHÔNG dùng systemctl reload nginx cho reload vhost aaPanel, vì systemd ExecReload gọi /usr/sbin/nginx và từng báo:
invalid PID number "" in "/run/nginx.pid"

Lệnh chuẩn:

/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf
/etc/init.d/nginx reload

Hoặc:

/www/server/nginx/sbin/nginx -s reload -c /www/server/nginx/conf/nginx.conf

11. Vhost HTTP + HTTPS chuẩn
----------------------------
File:
/www/server/panel/vhost/nginx/checkin.joydigi.net.conf

Cấu hình:

server {
    listen 80;
    listen [::]:80;
    server_name checkin.joydigi.net;

    location ^~ /.well-known/acme-challenge/ {
        alias /var/www/letsencrypt/.well-known/acme-challenge/;
        default_type text/plain;
        allow all;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name checkin.joydigi.net;

    ssl_certificate /etc/letsencrypt/live/checkin.joydigi.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/checkin.joydigi.net/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location /static/ {
        alias /var/www/joydigi-hr/staticfiles/;
        expires 30d;
        access_log off;
    }

    location /media/ {
        alias /var/www/joydigi-hr/media/;
        expires 30d;
        access_log off;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_connect_timeout 60s;
        proxy_send_timeout 120s;
        proxy_read_timeout 120s;
    }

    access_log /www/wwwlogs/checkin.joydigi.net.log;
    error_log /www/wwwlogs/checkin.joydigi.net.error.log;
}

Test + reload:

/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf
/etc/init.d/nginx reload

15. GitHub Actions tự deploy lên VPS
------------------------------------
Mô hình:
GitHub Actions -> SSH root@VPS -> /usr/local/bin/deploy-joydigi-hr -> git pull/reset -> pip -> migrate -> collectstatic -> restart service.

Tạo SSH key cho GitHub Actions đăng nhập VPS:

ssh-keygen -t ed25519 -f /root/.ssh/github_actions_vps -N "" -C "github-actions"
cat /root/.ssh/github_actions_vps.pub >> /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
cat /root/.ssh/github_actions_vps

Trong GitHub repository -> Settings -> Secrets and variables -> Actions, tạo:
VPS_HOST = 155.103.50.61
VPS_USER = root
VPS_SSH_KEY = nội dung private key /root/.ssh/github_actions_vps

Tạo /usr/local/bin/deploy-joydigi-hr:

#!/usr/bin/env bash
set -euo pipefail
APP_DIR="/var/www/joydigi-hr"
cd "$APP_DIR"

git fetch origin main
git reset --hard origin/main

if [ ! -d venv ]; then
    python3 -m venv venv
fi

./venv/bin/python -m pip install --upgrade pip setuptools wheel
./venv/bin/pip install -r requirements.txt
./venv/bin/pip install gunicorn
./venv/bin/python manage.py migrate --noinput
./venv/bin/python manage.py collectstatic --noinput
systemctl restart joydigi-hr

# Test nhanh, fail deploy nếu service không lên
sleep 2
systemctl is-active --quiet joydigi-hr
curl -fsS -o /dev/null http://127.0.0.1:8000/login/

echo "Deploy OK"

chmod +x /usr/local/bin/deploy-joydigi-hr

Workflow .github/workflows/deploy.yml:

name: Deploy JoyDigi HR

on:
  push:
    branches: [main]

concurrency:
  group: joydigi-hr-production
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - name: Configure SSH
        env:
          VPS_HOST: ${{ secrets.VPS_HOST }}
          VPS_SSH_KEY: ${{ secrets.VPS_SSH_KEY }}
        run: |
          mkdir -p ~/.ssh
          chmod 700 ~/.ssh
          printf '%s\n' "$VPS_SSH_KEY" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          ssh-keyscan -H "$VPS_HOST" >> ~/.ssh/known_hosts

      - name: Deploy
        env:
          VPS_HOST: ${{ secrets.VPS_HOST }}
          VPS_USER: ${{ secrets.VPS_USER }}
        run: |
          ssh -i ~/.ssh/id_ed25519 "$VPS_USER@$VPS_HOST" "/usr/local/bin/deploy-joydigi-hr"

NOTE: nếu branch chính là master thì thay main bằng master ở cả deploy script và workflow.

18. Các lệnh RESET - từ nhẹ đến mạnh
------------------------------------
A. Reset/restart ứng dụng - an toàn:

systemctl restart joydigi-hr
systemctl status joydigi-hr --no-pager -l

B. Reset Gunicorn khi port/process lạ:

systemctl stop joydigi-hr
pkill -f '/var/www/joydigi-hr/venv/bin/gunicorn' || true
ss -lntp | grep 8000 || true
systemctl start joydigi-hr

C. Reset virtualenv - không xóa database/media:

cd /var/www/joydigi-hr
systemctl stop joydigi-hr
rm -rf venv
python3 -m venv venv
./venv/bin/python -m pip install --upgrade pip setuptools wheel
./venv/bin/pip install -r requirements.txt
./venv/bin/pip install gunicorn
systemctl start joydigi-hr

D. Reset staticfiles:

cd /var/www/joydigi-hr
rm -rf staticfiles
./venv/bin/python manage.py collectstatic --noinput
systemctl restart joydigi-hr

E. Reset source về đúng GitHub - SẼ XÓA thay đổi code chưa commit:

cd /var/www/joydigi-hr
git fetch origin main
git reset --hard origin/main
git clean -fd -e .env -e media/ -e venv/

CẢNH BÁO: git reset --hard và git clean có thể làm mất file chưa commit. Backup trước.

F. Reset database hoàn toàn - CỰC KỲ NGUY HIỂM, XÓA TOÀN BỘ DỮ LIỆU HR:

systemctl stop joydigi-hr
pg_dump -U postgres -h localhost -Fc joydigi_hr > /root/backups/joydigi-hr/pre_reset_$(date +%Y%m%d_%H%M%S).dump
sudo -u postgres psql -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='joydigi_hr' AND pid <> pg_backend_pid();"
sudo -u postgres dropdb joydigi_hr
sudo -u postgres createdb -O postgres joydigi_hr
cd /var/www/joydigi-hr
./venv/bin/python manage.py migrate
systemctl start joydigi-hr

Chỉ chạy reset database khi CHẮC CHẮN muốn xóa dữ liệu production.

G. Restore database từ file .dump:

systemctl stop joydigi-hr
sudo -u postgres psql -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='joydigi_hr' AND pid <> pg_backend_pid();"
sudo -u postgres dropdb --if-exists joydigi_hr
sudo -u postgres createdb -O postgres joydigi_hr
pg_restore -U postgres -h localhost -d joydigi_hr --clean --if-exists /root/backups/joydigi-hr/FILE.dump
systemctl start joydigi-hr

H. Reset/reload aaPanel Nginx:

/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf
/etc/init.d/nginx reload

Nếu thực sự cần restart aaPanel Nginx:

/etc/init.d/nginx restart

Không dùng systemctl reload nginx trên VPS này.

19. Khi gặp lỗi - bảng xử lý nhanh
----------------------------------
KHI: systemd báo status=203/EXEC
NGUYÊN NHÂN THƯỜNG GẶP: ExecStart trỏ sai virtualenv hoặc gunicorn không tồn tại.
KIỂM TRA:
ls -la /var/www/joydigi-hr/venv/bin/gunicorn
cat /etc/systemd/system/joydigi-hr.service

KHI: Gunicorn status=3
NGUYÊN NHÂN: WSGI sai hoặc Django import lỗi.
PROJECT NÀY PHẢI DÙNG:
joydigi.wsgi:application
KIỂM TRA:
find /var/www/joydigi-hr -maxdepth 3 -name wsgi.py -print
./venv/bin/python -c "import joydigi.wsgi; print('WSGI OK')"

KHI: Address already in use 127.0.0.1:8000
NGUYÊN NHÂN: systemd Gunicorn đã chạy; không cần chạy gunicorn thủ công.
KIỂM TRA:
ss -lntp | grep 8000
systemctl status joydigi-hr

KHI: curl 127.0.0.1:8000 trả 302
ĐÂY LÀ BÌNH THƯỜNG nếu Location: /login/?next=/.

KHI: gõ http://127.0.0.1:8000 trong Bash và báo No such file or directory
URL không phải shell command. Dùng:
curl -I http://127.0.0.1:8000

KHI: systemctl reload nginx báo invalid PID /run/nginx.pid
VPS chạy aaPanel Nginx. Dùng:
/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf
/etc/init.d/nginx reload

KHI: ACME challenge public 404 nhưng local --resolve ra ssl-test
Vhost đúng, kiểm tra DNS/Cloudflare/AAAA. Test:
dig +short A checkin.joydigi.net
dig +short AAAA checkin.joydigi.net
curl --resolve checkin.joydigi.net:80:127.0.0.1 http://checkin.joydigi.net/.well-known/acme-challenge/test.txt

KHI: Nginx 502 Bad Gateway
Kiểm tra Gunicorn:
systemctl status joydigi-hr --no-pager -l
ss -lntp | grep 8000
journalctl -u joydigi-hr -n 100 --no-pager -l
curl -I http://127.0.0.1:8000

KHI: Django 400 Bad Request / DisallowedHost
Kiểm tra .env:
ALLOWED_HOSTS=checkin.joydigi.net,localhost,127.0.0.1
Sau đó:
systemctl restart joydigi-hr

KHI: CSRF verification failed trên HTTPS
Kiểm tra:
CSRF_TRUSTED_ORIGINS=https://checkin.joydigi.net
và Nginx gửi:
proxy_set_header X-Forwarded-Proto https;
Sau đó restart app.

KHI: PostgreSQL connection refused
Kiểm tra:

22. Ghi chú nâng cấp Python
---------------------------
Môi trường hiện tại từng chạy Python 3.10.12 và google.api_core cảnh báo ngừng hỗ trợ Python 3.10 trong các bản mới sau 04/10/2026.

Không nên đổi Python ngay giữa lúc production đang ổn định. Khi nâng cấp, tạo virtualenv mới riêng, cài requirements, chạy manage.py check/migrate trên staging hoặc maintenance window rồi mới đổi systemd PATH/ExecStart.

Ví dụ quy trình an toàn khi đã cài python3.12:

cd /var/www/joydigi-hr
python3.12 -m venv venv-py312
./venv-py312/bin/python -m pip install --upgrade pip setuptools wheel
./venv-py312/bin/pip install -r requirements.txt
./venv-py312/bin/pip install gunicorn
./venv-py312/bin/python manage.py check

Chỉ sau khi kiểm tra xong mới đổi service từ /venv/ sang /venv-py312/ rồi daemon-reload + restart. Giữ venv cũ để rollback nhanh.

23. Thứ tự rollback khi deploy lỗi
----------------------------------
1. Không reset database ngay.
2. Xem log: journalctl -u joydigi-hr -n 150 --no-pager -l
3. Nếu lỗi code mới, rollback source về commit trước:
   cd /var/www/joydigi-hr
   git log --oneline -10
   git reset --hard COMMIT_TOT
4. Nếu requirements thay đổi, cài lại requirements của commit đó.
5. Chạy manage.py check.
6. Nếu migration mới đã chạy và migration hỗ trợ reverse, cân nhắc migrate app_name migration_previous. Phải hiểu rõ migration trước khi reverse.
7. Restart joydigi-hr.
8. Test local rồi test HTTPS.
9. Chỉ restore database backup khi có bằng chứng database đã bị thay đổi hỏng và rollback migration không đủ.
