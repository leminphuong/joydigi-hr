2. KIỂM TRA PORT 80 / 443 / 8000
============================================================

# Xem tiến trình đang lắng nghe port 80, 443
ss -lntp | grep -E ':(80|443)\b'

# Xem port 8000 đang bị process nào chiếm
ss -lntp | grep ':8000'

# Xem đồng thời 80, 443, 8000
ss -lntp | grep -E ':(80|443|8000)\b'

# Xem tiến trình theo PID, ví dụ PID 770
ps -fp 770

# Xem command đầy đủ của PID 770
tr '\0' ' ' < /proc/770/cmdline
echo


============================================================
3. KIỂM TRA NGINX UBUNTU
============================================================

# Kiểm tra trạng thái nginx systemd
systemctl status nginx --no-pager -l

# Test cấu hình nginx Ubuntu
nginx -t

# Reload nginx Ubuntu
systemctl reload nginx

# Restart nginx Ubuntu
systemctl restart nginx

# Start nginx Ubuntu
systemctl start nginx

# Stop nginx Ubuntu
systemctl stop nginx

# Tắt tự khởi động nginx Ubuntu
systemctl disable nginx

# Bật tự khởi động nginx Ubuntu
systemctl enable nginx

# Xem PID nginx
cat /run/nginx.pid

# Xem toàn bộ process nginx
ps -eo pid,ppid,user,lstart,args | grep '[n]ginx'

# Xem binary thực tế của PID nginx
readlink -f /proc/894/exe

# Xem command line của PID nginx
tr '\0' ' ' < /proc/894/cmdline
echo

# Xem log nginx systemd
journalctl -u nginx -n 100 --no-pager -l

# Xem log lỗi nginx
tail -n 100 /var/log/nginx/error.log

4. NGINX AAPANEL
============================================================

# Test cấu hình nginx aaPanel
/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf

# Khởi động nginx aaPanel thủ công
/www/server/nginx/sbin/nginx -c /www/server/nginx/conf/nginx.conf

# Reload nginx aaPanel
/www/server/nginx/sbin/nginx -s reload

# Test rồi mới reload nginx aaPanel
/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf && /www/server/nginx/sbin/nginx -s reload

# Kiểm tra file nginx aaPanel
ls -lah /www/server/nginx/sbin/nginx
ls -lah /www/server/nginx/conf/nginx.conf

# Kiểm tra nginx aaPanel có include vhost không
grep -n "vhost/nginx" /www/server/nginx/conf/nginx.conf

5. KIỂM TRA VHOST WEBSITE AAPANEL
============================================================

# Liệt kê các vhost
ls -lah /www/server/panel/vhost/nginx/

# Xem cấu hình modbibi.com
sed -n '1,240p' /www/server/panel/vhost/nginx/modbibi.com.conf

# Xem cấu hình modpuro.com
sed -n '1,240p' /www/server/panel/vhost/nginx/modpuro.com.conf

# Tìm server_name modbibi.com
grep -Rni "server_name.*modbibi.com" /etc/nginx /www/server/panel/vhost/nginx /www/server/nginx/conf 2>/dev/null

# Kiểm tra nginx Ubuntu có load modbibi.com không
nginx -T 2>/dev/null | grep -n -B5 -A30 "modbibi.com"

# Xem include trong nginx Ubuntu
grep -n "include" /etc/nginx/nginx.conf

# Xem sites-enabled
ls -lah /etc/nginx/sites-enabled/

# Xem conf.d
ls -lah /etc/nginx/conf.d/

15. TRẠNG THÁI ĐÃ XÁC ĐỊNH TRONG LOG
============================================================

- Nginx Ubuntu /usr/sbin/nginx từng chiếm port 80.
- Nginx Ubuntu không load vhost modbibi.com.
- Port 443 từng không listen nên Cloudflare báo 521.
- Source WordPress modbibi.com và modpuro.com vẫn tồn tại.
- SSL fullchain.pem và privkey.pem của cả hai domain vẫn tồn tại.
- Nginx aaPanel test cấu hình thành công.
- Lệnh "systemctl stop nginx" đã dừng Nginx Ubuntu.
- Lệnh "/www/server/nginx/sbin/nginx -c /www/server/nginx/conf/nginx.conf" dùng để chạy Nginx aaPanel.
- "systemctl reload nginx" không reload được Nginx aaPanel nếu nginx.service đang inactive.
- JoyDigi HR Gunicorn đang bind 127.0.0.1:8000.
- Có process Python khác từng chiếm 0.0.0.0:8000.
- Vì port 8000 bị chiếm nên JoyDigi HR báo "Address already in use".

17. LƯU Ý
============================================================

1. Luôn chạy nginx -t trước khi reload/restart Nginx.
2. Không kill PID khi chưa kiểm tra process bằng ps -fp PID.
3. Không chạy đồng thời Nginx Ubuntu và Nginx aaPanel nếu cả hai cùng muốn dùng port 80/443.
4. Nếu dùng Nginx aaPanel cho website, nên tránh để Nginx Ubuntu tự động chiếm port sau reboot.
5. Với JoyDigi HR, chỉ một process/service nên giữ port 8000.
